# Augmentation of SLM Risk Assessment with Explainable Social Engineering Detection Evidence

An AI-powered **social engineering detection system** that combines transformer-based classification, multi-label social-engineering technique detection, explainable AI (XAI), and a locally deployed small language model (SLM) risk assessor.

The project investigates whether **explainable evidence generated by a specialised detection system can improve the reliability, relevance, and quality of risk assessments produced by a compact language model**.

Rather than treating the language model as the primary detector, the system separates **statistical detection** from **contextual risk assessment**: specialised neural models identify and explain indicators of social engineering, while a local SLM independently assesses the original message and uses the generated evidence as supplementary decision support.

---

## Project Overview

Social engineering messages are difficult to assess automatically because malicious intent is often expressed through subtle contextual and linguistic cues rather than simple keywords.

This creates two complementary problems:

1. **Neural classifiers** can provide accurate predictions but are difficult to interpret because their decisions are effectively black-box outputs.
2. **Language models** can provide nuanced reasoning but are susceptible to hallucination, unsupported assumptions, and inconsistent risk judgements.

This project explores a synergistic approach:

> **Use specialised, explainable neural-network predictions as evidence that augments—but does not determine—a local language model's risk assessment.**

The resulting system provides structured detection evidence containing:

- malicious probability;
- overall risk level;
- token-level explanatory evidence;
- detected social-engineering techniques;
- technique probabilities;
- supporting textual indicators.

This evidence is subsequently provided to a local SLM alongside the original message.

The SLM is instructed to assess the message independently and use the detection evidence to **support, challenge, or refine** its interpretation rather than treating the evidence as ground truth.

---

## Research Aim

The primary research question evolved from evaluating explanation *faithfulness* toward a more practical question:

> **Does explainable social-engineering detection evidence improve the reliability and quality of risk assessment produced by a small parameter language model?**

The investigation therefore compares SLM assessments under three conditions:

| Condition | Description |
|---|---|
| **C1 — No Evidence** | The SLM receives only the original message. |
| **C2 — Baseline Evidence** | The SLM receives evidence generated using a conventional TF-IDF + Logistic Regression detector. |
| **C3 — BERT/XAI Evidence** | The SLM receives evidence generated by the transformer-based detection system and its XAI components. |

The experiment does **not** assume that additional evidence will necessarily improve performance. Evidence may support, challenge, refine, or potentially degrade the SLM's judgement.

# System Architecture

The system consists of several specialised components rather than relying on a single general-purpose language model.

```text
                         ┌──────────────────────┐
                         │   Social Engineering │
                         │       Message        │
                         └──────────┬───────────┘
                                    │
                    ┌───────────────┴───────────────┐
                    │                               │
                    ▼                               ▼
          ┌──────────────────┐            ┌─────────────────────┐
          │ Binary Detection │            │ Technique Detection │
          │    ModernBERT    │            │    ModernBERT       │
          └────────┬─────────┘            └──────────┬──────────┘
                   │                                  │
                   │                                  ▼
                   │                       ┌────────────────────┐
                   │                       │ XAI / Evidence     │
                   │                       │ Generation         │
                   │                       └─────────┬──────────┘
                   │                                 │
                   └──────────────┬──────────────────┘
                                  ▼
                         ┌────────────────────┐
                         │ Structured         │
                         │ Detection Evidence │
                         └─────────┬──────────┘
                                   │
                                   ▼
                         ┌────────────────────┐
                         │ Local SLM Risk     │
                         │ Assessor            │
                         └─────────┬──────────┘

                         │ & Justification    │
                         └────────────────────┘
```

The architecture deliberately separates:

- **detection** — "Does this message exhibit malicious/social-engineering characteristics?"
- **explanation** — "What evidence contributed to those predictions?"
- **risk assessment** — "Given the message and available evidence, what level of risk does it represent and why?"

# 1. Binary Social Engineering Detection

The first classifier determines whether a message is **benign or malicious**.

### Model

The primary classifier uses:

- **ModernBERT-base** (`answerdotai/ModernBERT-base`)
- mean-pooled representations;
- dropout;
- a single classification logit;
- `BCEWithLogitsLoss`;
- sigmoid transformation for probability estimation.

The classifier produces a malicious probability rather than directly generating a textual explanation.

The probability is subsequently used as part of the structured evidence supplied to the risk assessor.

### Dataset

The dataset was progressively enriched to approximately **51,000 messages**, with the final corpus close to a 50:50 benign/malicious distribution.

Data preparation included:

- combining multiple public sources;
- removing exact duplicates;
- reducing highly similar duplicate campaigns;
- removing the CNN Top 10 dataset;
- enriching the corpus with additional examples;
- maintaining a near-balanced malicious/benign distribution.

The dataset was separated into training and evaluation components, with class balancing strategies applied differently to training and evaluation data where appropriate.

---

# 2. Social Engineering Technique Detection

A second transformer model performs **multi-label classification** of social-engineering techniques.

A single message can contain multiple techniques simultaneously.

The final taxonomy contains ten techniques:

1. **Urgency** — pressure to act quickly or immediately.
2. **Authority** — invoking an apparently legitimate or powerful authority figure or organisation.
3. **Fear** — threats, negative consequences, or anxiety intended to influence behaviour.
4. **Reciprocity** — exploiting an expectation that a favour, benefit, or action should be returned.
5. **Curiosity** — exploiting a user's desire to discover information or investigate something.
6. **Pretexting** — constructing a fabricated scenario or identity to obtain information or induce an action.
7. **Promotional** — using discounts, rewards, offers, or promotional incentives to encourage engagement.
8. **Transactional** — presenting an apparently routine task or transaction intended to induce an immediate action such as a transfer, click, or disclosure.
9. **Reminder** — presenting an interaction as a routine reminder, notification, or expected event.
10. **Personal** — exploiting personal circumstances, relationships, or personalised contextual information.

The model is trained as a multi-label classifier because techniques are not mutually exclusive.

Class imbalance in individual technique labels influenced the architecture and training methodology, including the use of cost-sensitive learning.

---

# 3. Explainable AI

The system incorporates XAI to convert otherwise opaque model predictions into interpretable evidence.

The project investigated and used transformer-compatible explanation methods including:

- **LIME**
- **SHAP**
- **Transformers Interpret**

The resulting explanations are retained separately from the underlying classifier outputs and are transformed into concise, human-readable evidence.

The purpose of XAI in this project is not simply to make a visualisation for a human user. Instead, the explanations become **structured evidence that can be passed to another model**.

This creates the central experimental mechanism of the project:

```text
Neural Network Prediction
          ↓
      XAI Analysis
          ↓
Human-readable Evidence
          ↓
Local SLM Risk Assessment
```

---

# 4. Detection Evidence

The detection system consolidates its outputs into a compact evidence representation.

A typical evidence report contains information such as:

```text
Classification:
Malicious probability: 1.00
Risk level: Critical
Evidence: subscription, information, URL, ...

Detected techniques:
- Urgency (9.1%): no prominent evidence
- Fear (5.9%): no prominent evidence
- Authority (13.8%): ...
- Promotional (40.2%): ...
...
```

The evidence is deliberately kept compact so that it provides useful contextual information without overwhelming the local language model.

Importantly, **probabilities and explanations are treated as evidence, not truth**.

For example:

- a high malicious probability does not automatically prove malicious intent;
- a detected technique does not necessarily mean that the technique is genuinely present;
- token-level importance does not constitute causal proof;
- the SLM must still interpret the original message.

This distinction is central to the experimental design.

---

# 5. Risk Assessment with a Local SLM

The final component is a locally deployed small parameter language model.

The SLM receives:

1. the original message;
2. optionally, the structured detection evidence;
3. a fixed risk-assessment task prompt.

The prompt explicitly instructs the model to assess the original message first.

The supplied evidence can:

- **support** an interpretation;
- **challenge** an interpretation;
- **refine** an interpretation.

It cannot directly determine the final risk level.

The SLM is also instructed to:

- distinguish explicit statements from reasonable inferences;
- avoid inventing external facts;
- avoid assuming hidden motives;
- treat ambiguity as uncertainty;
- independently determine the final risk level;
- use the evidence as contextual decision support rather than ground truth.

### Risk Levels

The final assessment uses four risk levels:

- **Low**
- **Moderate**
- **High**
- **Critical**

The assessment prompt follows a consistent structure covering relevant factors such as:

- objective of the message;
- requested action;
- detected techniques;
- indicators of risk;
- contextual uncertainty;
- potential consequences;
- overall justification;
- recommended guidance.

Sections that are irrelevant to a particular message can be reported as **"Not applicable"** rather than forcing the model to generate irrelevant content.

# 6. Evaluation Methodology

The project evaluates whether the detection evidence actually improves the SLM rather than assuming that explainability automatically provides value.

## Experimental Conditions

Each message is assessed under three conditions:

### C1 — No Evidence

```text
Original Message
       ↓
     SLM
       ↓
Risk Assessment
```

### C2 — Baseline Evidence

A conventional TF-IDF + Logistic Regression classifier provides the evidence.

```text
Original Message
       ↓
TF-IDF + Logistic Regression
       ↓
Baseline Evidence
       ↓
      SLM
       ↓
Risk Assessment
```

### C3 — BERT/XAI Evidence

The proposed transformer/XAI detection system provides the evidence.

```text
Original Message
       ↓
ModernBERT Detection System
       ↓
XAI + Technique Evidence
       ↓
      SLM
       ↓
Risk Assessment
```

This three-way comparison allows the project to distinguish between:

- the effect of providing **any** additional evidence;
- the effect of conventional classifier evidence;
- the effect of the proposed transformer/XAI evidence.

---

# 7. Prometheus 2 Evaluation

The SLM outputs are evaluated using **Prometheus 2**, a specialised open-source language-model evaluator.

The evaluator is run locally to maintain a reproducible and self-contained evaluation pipeline.

The current hardware target is an **NVIDIA RTX 3060 Ti with 8 GB VRAM**, with a quantised Prometheus 2 model selected to fit within the available hardware.

The evaluation uses a fixed rubric and evaluates each risk assessment on a **1–5 scale**.

### Primary Evaluation Criteria

The assessment focuses on:

1. **Risk appropriateness** — whether the assigned risk level is appropriate for the message.
2. **Relevance** — whether the assessment addresses the important characteristics of the message.
3. **Justification quality** — whether the reasoning provides a coherent and defensible explanation.
4. **Completeness** — whether important risk factors and contextual information are considered.
5. **Evidence-informed reasoning** — whether supplied evidence is interpreted appropriately without being treated as unquestionable truth.

---

# 8. Evaluation Dataset

To keep the evaluation practical while maintaining meaningful coverage, the primary evaluation set contains **30 fixed messages**:

| Category | Samples |
|---|---:|
| Benign | 10 |
| Malicious | 10 |
| Ambiguous / difficult | 10 |
| **Total** | **30** |

Each message is evaluated under all three experimental conditions.

This produces:

**30 messages × 3 conditions = 90 primary assessments**

A smaller repeated subset is additionally used to examine the stability of the evidence-augmented condition.

The dataset intentionally includes ambiguous or difficult examples because an evaluation consisting only of obvious phishing and obviously benign messages would provide limited insight into whether evidence actually helps with nuanced risk assessment.

---

# 9. Statistical Analysis

The primary comparison considers the paired nature of the experimental conditions, since the same messages are evaluated under each condition.

Planned analysis includes:

- descriptive statistics for each evaluation criterion;
- comparison of score distributions across conditions;
- **Friedman tests** for overall differences across the three related conditions;
- **Wilcoxon signed-rank tests** for planned pairwise comparisons.

The principal comparisons are:

```text
C1 vs C2
C1 vs C3
C2 vs C3
```

The most important comparison is **C2 vs C3**, which tests whether the proposed BERT/XAI evidence provides an advantage beyond simply giving the SLM conventional classifier evidence.

---

# 10. Calibration

Because the binary detector produces probabilities that are subsequently exposed as evidence, probability calibration is an important part of the system.

Calibration was investigated using:

- reliability diagrams;
- Brier score;
- log loss;
- calibration thresholds;
- temperature scaling;
- Platt scaling.

Temperature scaling did not provide the desired improvement in this implementation.

Platt scaling produced substantially better calibration performance, including improvements in Brier score and log loss, and was therefore preferred for probability calibration.

The calibrated probability can then be communicated as a more meaningful estimate of the classifier's confidence rather than an unexamined neural-network output.

---

# 11. Automated Technique Annotation

Because large-scale multi-label technique annotation is expensive to perform manually, an LLM-assisted annotation pipeline was developed during dataset construction.

The annotation pipeline uses structured outputs to assign the ten technique labels to messages.

Each annotation contains:

- a Boolean technique label;
- an associated confidence value;
- stable message identifiers;
- annotation metadata.

The pipeline supports:

- batched processing;
- structured validation;
- retries;
- checkpointing;
- resumability;
- stable mapping between source messages and annotations.

These annotations are used as training data for the multi-label technique detector rather than allowing the downstream risk assessor to directly rely on an external API.

# 12. Design Philosophy

Several principles guide the system.

### Separation of detection and reasoning

The classifier and SLM have different roles.

The classifier specialises in detecting statistical patterns associated with social engineering.

The SLM specialises in contextual interpretation and natural-language risk assessment.

Neither component is expected to perform the other's task perfectly.

### Evidence rather than ground truth

The detection system's output is explicitly presented as evidence.

The SLM is expected to retain independent judgement.

### Local inference

The final risk-assessment experiment is designed around local model inference rather than sending potentially sensitive message content to an external commercial LLM API.

This also makes the experimental setup more reproducible and appropriate for privacy-sensitive applications.

### Reliability over perfect faithfulness

The project initially considered evaluating whether the SLM faithfully followed the supplied XAI evidence.

However, this was narrowed because strict evidence faithfulness can become undesirable: a risk assessor should not blindly reproduce an incorrect classifier prediction simply because an explanation was provided.

The final objective is therefore broader and more practically meaningful:

> **Does the evidence help the SLM make a more reliable, grounded, and appropriate risk assessment?**

# 13. Example End-to-End Flow

A message enters the system:

```text
"Your subscription payment failed.
Please verify your information using the link below..."
```

The binary classifier may produce:

```text
Malicious probability: 1.00
Risk level: Critical
```

The technique classifier may identify evidence associated with:

```text
Promotional
Transactional
Authority
Urgency
```

XAI methods then identify influential textual indicators such as:

```text
subscription
information
URL
payment
verify
```

The resulting evidence is provided to the SLM.

The SLM does **not** simply receive:

```text
"Classifier says this is Critical."
```

Instead, it receives contextual evidence and is instructed to reason independently.

It may therefore conclude that:

- the message requests sensitive information;
- the request is framed as a routine subscription/payment action;
- a URL is used to facilitate the requested action;
- several social-engineering indicators are present;
- the evidence supports a high level of concern;
- uncertainty should still be acknowledged where appropriate.

The quality of this reasoning is then evaluated by Prometheus 2.

# 16. Limitations

Several limitations are deliberately recognised:

- LLM-assisted technique annotations may contain annotation noise or systematic biases.
- XAI feature importance should not be interpreted as causal evidence.
- The SLM's output can vary with model, quantisation, prompt, and sampling parameters.
- Prometheus 2 is itself a language model and therefore represents an evaluator rather than an absolute ground truth.
- The evaluation dataset is intentionally small enough to permit detailed controlled experimentation.
- The ten-technique taxonomy does not encompass every possible social-engineering strategy.
- Local SLM inference imposes hardware and model-size constraints.
- Evidence generated by an imperfect detector can potentially introduce misleading information rather than improve an assessment.

These limitations are particularly important because the central research question concerns whether model-generated evidence is **actually useful**, rather than assuming that interpretability inherently improves decision-making.

## Research Summary

In one sentence, the project asks:

> **Can interpretable evidence from a specialised social-engineering detection system make a small local language model a more reliable risk assessor?**

The system addresses this question by combining **ModernBERT detection, multi-label technique classification, probability calibration, XAI, structured evidence generation, local SLM reasoning, and controlled Prometheus 2 evaluation**.
